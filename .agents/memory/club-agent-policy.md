The user named the bot **Club Agent** and supplied its image. Development tiers are **Trialist → Academia Prospect → First Team Roster**.

**Why:** The user explicitly confirmed the name and tier sequence.

**How to apply:** Preserve this branding and progression unless the user changes them.

The user accepted **80% over 30 days with at least five sessions for now**, but emphasized flexibility for people's availability and vacation/time away. Attendance is a factor in staff-controlled promotion, not a standalone automatic promotion or a penalty for limited declared availability.

**Why:** The user wants to keep up with attendance without disadvantaging players for legitimate time away or varying availability.

**How to apply:** Keep the standard adjustable, preserve approved leave/excused-absence protections, and distinguish unmarked attendance from no-shows.

The user wants a "start here" workflow so people know where to go, rather than confronting a large command list.

**Why:** The user found the number of commands overwhelming.

**How to apply:** Introduce features through concise, role-appropriate next-action guidance; keep detailed command lists as a reference rather than the main onboarding experience.

Saved guide positions are "optional navigation continuity, not a record that the user
completed any real-world action."

**Why:** The user explicitly separated resuming guidance from performing or completing club work.

**How to apply:** Do not use guide navigation as evidence of setup, attendance, recruitment,
or task completion, or let browsing execute the suggested actions.

The companion website's first release is a public site with bot features and "why we're
different," plus a private admin UI. Public/player development dashboards come later.

**Why:** The user explicitly requested both website surfaces but prioritized "Right now private
admin UI with complete optimization" and deferred the player development dashboard.

**How to apply:** Build the public explanation and real private administration together, without
exposing player development, scouting, or attendance records publicly. The earlier bot-only scope
does not prohibit this requested companion website.

The user confirmed that members with the Trialist and Dev Squad roles should have access to
`#staff-reports`.

**Why:** The user explicitly chose to keep their View Channel access after the live audit.

**How to apply:** Preserve these two role grants unless the user changes the intended audience.
